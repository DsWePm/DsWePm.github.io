## 这一篇要学什么

读完这一篇，应当能够：

1. 说出“残差学习”是什么，并能算出 PID 命令和修正量合成后的结果；
2. 解释为什么执行时用的网络（Actor）可以很小，而只在训练时用的网络（Critic）可以很大；
3. 区分“网络算得快不快”和“数据旧不旧”，说明车上的时延主要花在哪里；
4. 说出训练中保证模型确实更好的几项做法，以及为什么不能拿训练奖励当验收标准。

> 重点：混合公式；Actor 和 Critic 的分工；用与奖励无关的开发集选模型。
>
> 难点：为什么要先冻结 Actor；为什么大的 Critic 不一定更好。

预备知识：知道强化学习的基本思路，即程序在环境里行动，根据得到的奖励改进自己的做法。

## 先看一个问题

纯靠神经网络从零学开车，一开始的动作是乱的，要经过大量试错才学得会。纯靠 PID，在没见过的情形里（例如绕过一块板）又做不出合适的动作。一个自然的想法是：让 PID 先把车开稳，神经网络只学“在 PID 的基础上怎样修正”。

这一篇讲这个想法怎样落实，以及落实以后要回答的三个问题：两个网络为什么不必一样大，车上的延迟花在哪里，训练怎样做才靠得住。

先认几个词。

| 名称 | 意思 |
| --- | --- |
| PID 控制器 | 经典的反馈控制方法。按“现在的误差、过去累积的误差、误差变化的快慢”三项来修正命令，分别叫比例、积分、微分。这里不使用积分项 |
| 强化学习 | 程序通过试错、根据奖励来改进动作的学习方法 |
| SAC | 一种强化学习算法，由 Actor 和 Critic 两部分网络组成 |
| Actor | 策略网络：看到观测，给出动作（这里是驱动和转向的修正量） |
| Critic | 价值网络：给“在某个观测下做某个动作”打分，用来指导 Actor 改进 |
| 行为克隆 | 模仿学习的一种：让网络直接学习教师给出的命令 |
| 回放缓冲区 | 存放最近一段时间的经验（观测、动作、奖励），供训练反复取用 |
| 回合 | 从开始到结束的一次完整试跑 |
| 开发集 | 固定不变的一批试跑用例，只用来比较和挑选模型 |

## PID 打底，网络只管修正

在已有控制器的输出上再加一个由网络给出的修正量，这种做法叫**残差学习**。这里的底座是 PID，学习部分是 SAC。

PID 只读 obs18（上一篇讲过的 18 个观测数），不保存积分状态。驱动命令由“速度前馈”和“速度比例项”组成，目标速度由可靠的路有多长、弯有多急决定。转向命令由横向偏差、航向偏差、车身转动的阻尼，以及前方 1 m 目标的“预瞄”项组成。参考线无效时，PID 自己刹车、转向归零，不做任何猜测。

积分项的系数取 0，是有意的。这样 18 个数就足以描述 PID 的行为，控制器里没有藏着看不见的状态。（但 18 个数仍不能完整描述规则和历史的全部状态，所以不声称“当前观测已包含决策所需的全部信息”，也不声称训练一定收敛。）

网络输出的修正量记作 a，范围是 −1 到 1。PID 的命令记作 p，范围也是 −1 到 1。合成的办法是：按修正的方向，用 p 那一侧“剩下的余量”来放大或缩小修正。

- a ≥ 0（往上修正）时，余量 = 1 − p；
- a < 0（往下修正）时，余量 = 1 + p；
- 最终命令 = p + 余量 × a。

**例：** 设 p = 0.6。

| 修正量 a | 余量 | 最终命令 |
| --- | --- | --- |
| 0 | 1 − 0.6 = 0.4 | 0.6 |
| +0.5 | 0.4 | 0.6 + 0.4 × 0.5 = 0.8 |
| +1 | 0.4 | 0.6 + 0.4 × 1 = 1.0 |
| −0.5 | 1 + 0.6 = 1.6 | 0.6 + 1.6 × (−0.5) = −0.2 |
| −1 | 1.6 | 0.6 + 1.6 × (−1) = −1.0 |

想一想：a = 0 时命令是多少？答：等于 p，也就是纯 PID 的命令。

写成程序只有三行：

```python
correction = np.clip(scale * residual, -1., 1.)               # 把网络的修正量限制在 -1 到 1
room = np.where(correction >= 0, 1. - base, 1. + base)         # 往哪个方向修正，就用哪一侧的余量
command = np.clip(base + room * correction, -1., 1.)           # 合成后的命令
```

![混合公式：命令 = p + 余量 × a。(a)(b) 驱动和转向的混合函数：灰线是其他 p 值下的曲线，橙色粗线是此刻的 p，圆点是此刻的（a，命令）。无论 p 取何值，a 从 −1 变到 +1，命令都恰好从 −1 变到 +1，a = 0 时命令等于 p。(c)(d) 真实仿真中一段通过障碍板的时间序列：灰线是 PID 的命令，浅蓝线是网络的修正量，深蓝线是合成后的命令，橙色底表示绕障规则在控制，混合不起作用。用公式算出的结果与仿真里记录的命令逐步比较，最大差为 0。](notes/sac-pid-asymmetric-actor-critic/mixer.gif)

这种合成方式有几个好处。

修正量为 0 时，命令就是 PID 的命令。训练刚开始时，网络的输出接近 0，车的行为就是一个能用的 PID，不必从零开始乱试。

命令不会超出范围。合成后的命令始终在 −1 到 1 之间，不会出现“网络要 1.5、实际只能给 1”的情况。被截掉的那部分动作对学习没有用，还会让学习所依据的信号失真。

PID 给不出有效命令时（参考线无效），学习部分让位：这时不给网络任何学习信号，只由 PID 的刹车和行为克隆去处理。

还有一点关系到训练。训练时，Critic 评价的对象，是合成并经过命令检查之后的“虚拟请求”（还没有换成真实的油门），而不是网络原始输出的修正量。为此，用 torch 重写了一份 PID、混合和输出换算的版本，它可以求导，训练所需的学习信号能够穿过它传回网络。这样 Critic 评价的就是车真正会去做的那个命令。

## 执行时的网络小，训练时的网络大

在 SAC 里，Actor 和 Critic 不必一样大。这里的做法是：Actor 很小，要上车；Critic 大得多，只在训练时用；教师也只在训练时出现。文献里常说的“非对称 Actor-Critic”多指 Critic 能看到比 Actor 更多的信息，这里的不对称主要在规模和使用的地方：Critic 看到的仍是 18 个观测加命令，教师掌握的额外信息只通过命令标签进入训练。

先算一下规模。Actor 的结构是 18 → 256 → 256 → 2：输入 18 个数，经过两个各有 256 个节点的中间层，输出 2 个数（驱动和转向的修正）。参数个数是 18×256+256（4,864）加 256×256+256（65,792）再加 256×2+2（514），合计 71,170。Critic 的输入是 18 个观测和 2 个命令，共 20 个数，结构是 20 → 512 → 512 → 1，参数个数是 10,752 + 262,656 + 513，合计 273,921，约是 Actor 的 4 倍。训练时用两个独立的 Critic，取其中较小的打分，防止对价值估计过高。

| 部分 | 结构 | 参数个数 | 用在哪里 |
| --- | --- | --- | --- |
| Actor | 18 → 256 → 256 → 2 | 71,170 | 训练和上车 |
| 探索用的标准差输出 | 与 Actor 共用中间层 | 很少 | 只在训练时用：让动作带一点随机性，上车时只用均值 |
| 两个 Critic | 20 → 512 → 512 → 1 | 各 273,921 | 只在训练时用 |
| 教师 | 知道道路和板子的真实几何 | 不适用 | 只在训练时用，只提供命令标签 |

代码里把这一版叫 FT512，512 指 Critic 的宽度，不是 Actor 的宽度。

这样分工有几个好处。

上车的部分小，可以逐项检查。车上只有 6 个数组（三层的权重和偏置）和一段用 NumPy 写的前向计算，不需要 torch，不需要 GPU，也不需要另一套模型加载程序。

Critic 的大小只影响训练的开销，不影响车上的延迟，所以可以取得较大。

教师的信息不会泄漏到部署的输入里。教师看得到道路和板子的真实几何，但这些信息只变成“该输出什么命令”的标签，用来训练 Actor。Actor 的输入始终是同样的 18 个数，训练和上车用的是同一个观测。

![训练时和上车时各有什么。训练机上有仿真器、GPU 上的回放缓冲区、教师、两个 Critic 和 Actor。上车只带 6 个数组（actor_mean.npz），用 NumPy 做均值推理，再接 PID、混合、规则和检查。教师的标签只通过行为克隆的损失进入 Actor。Critic 的参数约是 Actor 的 4 倍（273,921 对 71,170），因为它只需要在学习时是对的。](notes/sac-pid-asymmetric-actor-critic/asymmetric.svg)

有一种常见的想法：Critic 越大越好。实际对比是这样的：宽度 512 的 Critic 和宽度 1024 外加归一化层的 Critic，在开发集上分别是 55/58 和 53/58，小的反而略好，开发集上的安全表现也更好。但两个模型的来源和归一化方式不同，所以这不是单纯比较宽度的实验，不能据此说“更大没有用”。

## 车上的延迟：先量，再下结论

先分清两个量。推理耗时，是网络从拿到输入到给出输出用的时间。数据的年龄，是数据从被传感器采集，到被控制器用上，中间已经过去的时间。

在车上测过推理耗时（车辆没有使能，传感器服务照常运行）。下表里的“第 99 百分位”，是把耗时从小到大排，排在 99% 位置的那一个，可以理解为“几乎最坏”的情形。

| 测量对象 | 结果 | 说明 |
| --- | --- | --- |
| 单独运行 Actor | 第 99 百分位 1.529 ms | 901 次调用的一条连续记录 |
| PID 加 Actor | 第 99 百分位 3.560 ms | 同上 |
| 宽 64、128、256 的网络 | 第 99 百分位 1–3.4 ms | 其中宽 128、256 的用随机权重，只测算力，不代表训练好的策略 |
| 整条集成链运行一步 | 中位数 49 ms，最大 131 ms | 远低于 0.5 s 的响应期限；控制周期是 0.1 s |

在笔记本上又把真实的推理路径量了一遍（同一份最终权重，真实观测，20,000 次调用）：

| 路径（Windows 笔记本，单线程） | 中位数 | 第 99 百分位 |
| --- | --- | --- |
| 用 NumPy 算的 Actor | 21 µs | 34 µs |
| Actor、PID、混合、限速、换算 | 107 µs | 256 µs |
| 同一个 Actor，用 torch 在 CPU 上算 | 56 µs | 117 µs |

![推理耗时的比较（对数坐标）。深蓝是在笔记本上测到的 NumPy Actor 和整条命令路径，浅蓝是同一个网络用 PyTorch 在 CPU 上的耗时，橙色是车上的记录。灰色虚线是 100 ms 的控制周期，橙色虚线是 0.5 s 的期限。从微秒到毫秒，推理离预算差两到四个数量级。](notes/sac-pid-asymmetric-actor-critic/latency.gif)

由此得到两点。

第一，推理不是主要开销。从微秒到毫秒，离一个 100 ms 的周期还差两到四个数量级。把网络做小、用 NumPy 来算，是为了部署简单、便于检查，不是为了省这点时间。

第二，主要的延迟在数据的年龄。两份实车诊断记录（共 360 行）显示：相机数据被用上时，中位数已经是 264 ms 以前的，激光数据是 153 ms 以前的；完整的策略计算耗时中位数 50 ms，最大 62.7 ms；步周期的中位数 100.2 ms。

**算一算：** 车速 0.45 m/s 时，264 ms 相当于车已经走了约 0.12 m。网络再快，看到的也是 0.12 m 以前的画面。

车上保证延迟，采取了几项做法：

- 车上只带 NumPy。全部运行代码、固定参数和权重都放在一个节点文件里，车上只需要 ROS 的依赖和 NumPy。模块在节点启动时加载一次，切换控制器时不必重新解码权重。
- 每一步的工作量有上限。观测程序遇到过大的帧（激光超过 2048 点、检测超过 40 个）就直接停车，不截掉一部分再声称“剩下的空间是空的”。第一篇讲的缓存和格子，也是为了让一步的最坏耗时有上限。
- 时限算的是整个回调，不只是 Actor。绕障时“丢了路也允许再走一小段”的条件里，单步不超过 0.12 s，量的就是整个回调。
- 自动化测试不用耗时做判定。笔记本上的耗时不是车上的期限，车上的数以车上的实测为准。

## 训练：怎样确保模型确实更好

最终使用的版本叫 V6。它从已经上过车的上一版（V5）出发，在一个更接近实车的仿真里继续训练，这个仿真在下一篇讲。训练分几步，每一步都有理由。

1. 先冻结 Actor，只训练 Critic。起点是 V5 的 Actor，以及它最终的 Critic 和目标网络（目标网络是 Critic 的一个缓慢更新的副本，用来计算学习目标）。可是仿真里传感器和油门的特性变了，旧的 Critic 打出的分数不再可信。所以先收集 5,000 步经验，再让开头的 20,000 次更新只训练 Critic，之后才让 Actor 一起学。优化器的状态、控制探索强度的“温度”和回放缓冲区都从头开始，因此这是一次新的微调，不是在旧数据上继续训练。
2. 训练时一直带着行为克隆。Actor 的损失里始终有一项行为克隆，权重约 80，让 Actor 的输出向教师的命令靠拢。教师的命令包括绕行过程中保持一侧的专门样本，以及 432 条紧贴锥桶线通过的额外示范。失败的教师回合和它们的前半段一律不用，不因为前半段看起来好就留下。
3. 学习率取得很小。具体设置见下表。
4. 任务按固定比例抽取。每个回合有 25% 是空路，55% 是可以通过的板子（其中一半紧贴锥桶线），20% 是完全堵死的路。紧贴锥桶线的板子最难，所以刻意多抽。
5. 奖励只是训练信号。前进的奖励只在道路已知时给，并按航向偏差打折。时间、横向偏差、航向偏差、转向用力、超速、“路未知还开得快”都要扣分。靠近板子时，把“贴中线”的权重从 2.0 降到 0.35，免得车为了贴中线而不敢绕行。安全通过板子加 5，跑完全程加 10，确认路堵死后停车加 5，碰撞、越界和被禁止的倒车扣 50。原地不动也要扣分，合理的停车除外。“停滞”按回合中途被截断处理，不当作失败结束，这样“本来能过却停了”和“本来就该停”才分得开。
6. 用与奖励无关的开发集选模型。每训练 20,000 步，在 57 个固定回合上评一次候选的 Actor。比较的顺序是：先比成功的回合数，相同再比绕过板子的数量、碰撞数、越界数。候选更好才替换当前保留的 Actor，否则保留原来的。

| 设置 | 取值 | 作用 |
| --- | --- | --- |
| Actor 的学习率 | 1e-5 | 每次更新的步子大小。取得小，是为了不把已有的好行为改坏 |
| Critic、温度的学习率 | 1e-4 | 同上，Critic 学得快一些 |
| 折扣系数 | 0.99 | 对未来奖励的看重程度 |
| 目标网络的更新系数 | 0.005 | 目标网络每次向 Critic 靠近多少 |
| 批大小 | 256 | 每次更新用多少条经验 |
| 回放缓冲区 | 200,000 条 | 最多存多少条经验 |
| 初始熵系数、目标熵 | 0.1、−2 | 控制动作的随机程度，系数越大越鼓励探索 |
| 行为克隆的权重 | 约 80 | 模仿教师的力度 |

## 例题：为什么不能只看总分

为什么要保留行为克隆，又为什么不能只看一个总分？看早先的一次对照（同样的随机种子 41、网络宽 128、100 万步，同样的 PID、观测和环境）：

| 控制器 | 固定回归集（200 个场景）的综合任务分，满分 100 | 压力场景（160 个）中的越界次数 |
| --- | --- | --- |
| 同参数的纯 PID | 60.03 | 21 |
| SAC 加 PID，不模仿 | 42.91 | 20 |
| SAC 加 PID，带模仿 | 72.85 | 31 |

加入模仿以后，总分明显提高（与纯 PID 的差，95% 区间为 [7.01, 18.65]），压力场景里的越界次数却增加了。所以后来一直保留行为克隆，并且按类别单独评价，而不是只看训练奖励或一个总分。这组对照不能说明模仿一定更安全，也分不清 PID 对最终控制器的贡献。

## 从训练记录里读到的几点

- 刚开始微调时，成绩先下降。40k 到 120k 步，开发集成功数降到 24–27（碰撞一度到 11），之后才回升。只看训练曲线，很容易在这里放弃。
- 最后上车的不是最后一个检查点。保留下来的是 580k 步的那一个：开发集 36/57，绕过板子 27 个，碰撞 4 次，越界 3 次。最后一个检查点（600k）只有 33/57。起点，也就是 V5 的 Actor 放进新仿真，是 28/57。
- 训练更久不一定更好。300k 步以后接着训练到 600k，训练中的成功率几乎没变（约 0.6），开发集上的最好成绩从 34 升到 36。Critic 的损失和行为克隆的误差很早就不再下降。
- 样本有限。只有一个随机种子，示范只选了成功的回合，所以方差和覆盖范围都有限，开发集上的排名不能当作安全的证明。

还有一个评测习惯：在责怪学生之前，先检验教师。V5 的教师最初只通过了 150 个固定资格回合中的 118 个，修正几何和可见性以后是 132 个，仍有失败。做法是检查完整的回合，只用通过的示范，不接受“前半段看着不错”的失败回合。

## 容易出错的地方

| 容易有的想法 | 实际情况 |
| --- | --- |
| 网络越大越好 | 宽度 512 的 Critic（55/58）比宽度 1024 加归一化层的（53/58）略好。但两个模型来源不同，不是单纯比宽度，不能据此说“大没有用” |
| 训练奖励越高，模型越好 | 奖励只是训练信号。选模型要用与奖励无关的开发集 |
| 最后一个检查点最好 | 最终使用的是第 580k 步的（36/57），最后一个（600k）只有 33/57 |
| 训练得越久越好 | 300k 到 600k 步，训练中的成功率几乎没变 |
| 网络算得快，延迟就小 | 主要的延迟在数据的年龄（相机约 264 ms），不在网络 |

## 适用范围和局限

- 只有一个随机种子，开发集被反复使用，没有独立留出的测试。
- 起点和对照来自不同的仿真时，不能直接比较大小。
- 最终的控制器是学习部分加规则，不能把成绩全部算到 Actor 头上。更大的 Critic 或更长的训练，也没有被证明能解决参考线缺失、油门死区、通行宽度标准不一致这类问题。

## 小结

> 板书
>
> - 命令 = PID 的命令 + 余量 × 修正量，修正量为 0 时就是纯 PID
> - Actor 小（71,170 个参数，上车），Critic 大（各 273,921 个，只在训练时用）
> - 延迟：推理是微秒到毫秒，数据的年龄是一百多到两百多毫秒
> - 训练：冻结 Actor 先校准 Critic，一直模仿教师，学习率很小，按比例抽任务，用与奖励无关的开发集选模型

完成 100 万步，或者平均分更高，都不足以说明模型好。需要同时看失败的类别、教师覆盖了哪些情形、“请求的动作”和“实际执行的动作”各是什么，以及参考线有没有依据。最终的方案是学习加实测的执行器特性，再加有边界的规则。“再训久一点就能修好每一种看不见的问题”，并没有被当作前提。

## 思考题

1. p = −0.4，a = +0.5，最终命令是多少？（参考答案：余量 1 − (−0.4) = 1.4，命令 = −0.4 + 1.4 × 0.5 = 0.3。）
2. 为什么微调开始以后，要先让 Critic 单独学一段时间？（提示：旧的分数依据的是旧的仿真。）
3. 车上推理耗时约 3 ms，传感器数据的年龄约 260 ms，要降低时延，应该先改哪一项？为什么？
