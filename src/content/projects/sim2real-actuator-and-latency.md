上一篇的控制器在仿真里训得不错，上车却是另一回事：同样的命令，小车**不动**；刹车之后如果还继续给负命令，它还会**倒着走**；转向的力度也不是仿真里的那个数。这一篇讲我怎样把"车上量到的东西"一件件装进仿真，再在这个更接近真车的仿真里微调。

先把话说在前面：这里装进仿真的"实测噪声"主要是**延迟、安装位置、无符号读数和参数的不确定范围**，我没有往传感器里注入高斯噪声，也没有注入随机丢帧。这个训练池是"干净的"，后面会具体说。

## 先量，再建模

仿真里原来的油门是"线性的"：命令大一点，推力就大一点。真车的电调不是这样。我先记录三件事：

1. **死区。** 在静止的车上，请求 0.30 不动，0.35 才起步；一旦动起来，维持运动所需的油门又比起步低。
2. **稳态速度表。** 一组稳态的"油门 → 速度"测量：0.30 → 0.27 m/s，0.32 → 0.56，0.34 → 0.67，0.36 → 0.86，0.38 → 0.99，0.40 → 1.08，0.42 → 1.16（更大的油门不是稳态，我没有用）。
3. **转向。** 满舵平均约 0.476 rad（左 0.463，右 0.489）；仿真里虚拟转向要乘 1.65 再截到 ±1。

稳态时驱动力和阻力平衡，速度平方应该和油门成线性关系：`v² / 10 = g·c + b`。我用最小二乘拟合那组表，得到

- 增益 `g = 1.0812`，
- 零速根（速度为 0 时对应的油门）`0.29305`。

![(a) 稳态油门—速度测量点（蓝点）和线性拟合（橙线），虚线是零速根 0.293。(b) 适配器：把控制器的虚拟请求 u 换成电调油门 c（调用的是仓库里的执行器适配器）：u ≤ 0.005 输出 0；起步时有一个 0.34 → 0.40 的爬升下限，随起步后的时间 t 变化。(c) 电机模型：把油门 c 换成有效推力，每个回合随机抽一组参数（动画里依次画出几次抽样，图下方一行是当前这次抽到的参数），蓝线是已经在动（0.5 m/s），橙线是从静止起步，虚线是维持和起步阈值。图最下面一行是每个回合抽样的范围。](notes/sim2real-actuator-and-latency/actuator.gif)

**这里有一个必须承认的限制：只有"零速根"能被辨识，起步 / 维持阈值和滚动阻力分不开。** 我把滚动阻力 `r` 取 0.03，是一个**假设**，由此得到维持阈值 `s = 0.2653`；起步阈值 0.335 是另外给定的，不是从这张表拟合出来的。我手里只有报告出来的这几个点，没有原始测量数据，所以标定文件里写明了每个数的出处和"这些数没有独立验证"，并规定不允许有人悄悄重新拟合。

有了这些，适配器（把控制器的虚拟请求 `u` 换成真实油门 `c`）就是拟合关系的反函数：

```python
throttle = hold + (u + rolling) / gain          # 反函数，零请求保持为零
if speed < .12:                                  # 起步时有一个时间相关的下限
    throttle = max(throttle, min(.40, .34 + .06 * t_since_start))
servo = clip(1.65 * steering)
```

仿真里的电机则反过来：油门不够起步就不动，不够维持就被拖慢，超过之后才有推力：

```python
if v < .03 and c < start:  return 0.                       # 静摩擦：起步不了
if c < hold:               return -min(drag_cap, drag_k*v) # 低于维持阈值：被拖慢
return gain * (c - hold)                                   # 正常推力
```

## 用范围，不用点

上面每个数都是在一辆车、一个电量、一个地面上量的。如果仿真里只放一组点估计，策略会学到"刚好适配这一组"。所以我在**每个回合**从一个范围里抽一组参数：

```python
CarParameters(
    gain=uniform(.95, 1.21),      hold=uniform(.245, .285),   start=uniform(.33, .40),
    max_steer_rad=uniform(.44, .51), steer_offset_rad=uniform(-.02, .02), drag_k=uniform(1.5, 2.5))
```

这些范围覆盖的是**不确定性**，不是"无限制的未知动力学"：车换了、电池换了、地面换了，它们不一定还成立，所以换车不能直接沿用这些标定。

## 把传感器的延迟、位置和符号装进仿真

真车上还有几件仿真里原来没有的事，我把它们都放进了 V6 仿真：

| 项目 | 车上 | 仿真里怎么做 |
| --- | --- | --- |
| 相机延迟 | 帧晚到，车上中位约 0.206 s | 每个回合抽 1 / 2 / 3 步（概率 25% / 50% / 25%，一步 0.1 s） |
| 激光延迟 | 比相机新 | 抽 0 / 1 / 2 步（25% / 50% / 25%） |
| 轮速延迟 | 编码器读数 | 抽 0 / 1 步（50% / 50%） |
| 相机位置 | 在重心后 0.10 m | 观测从这个位置算，被板子挡住的锥桶也**从相机处追射线**，不是从车身中心 |
| 激光位置 | 在重心前 0.20 m | 距离换算成车身坐标时用同一个平移 |
| 轮速符号 | 无符号的编码器读数 | 只给观测器绝对值，所以它分不清"停了"和"在倒车" |
| 电调倒车 | 持续的负命令在停车后会倒车 | **去掉**模拟器原来的"前进 → 倒车"闩锁，倒车被记为不安全 |

```python
CAMERA_DELAY_STEPS = ((1, .25), (2, .5), (3, .25))   # (步数, 概率)
LIDAR_DELAY_STEPS  = ((0, .25), (1, .5), (2, .25))
WHEEL_DELAY_STEPS  = ((0, .5), (1, .5))
...
# 观测器拿到的是"几步前"的那一帧，连同它真实的采集时间戳和年龄
cones, stamp, t = self.camera_frames[max(0, len(self.camera_frames) - 1 - self.camera_delay)]
```

![一个真实的 V6 仿真回合里，观测器拿到的相机帧和此刻最新的相机帧的差别。(a) 车身坐标系：空心圈是最新的相机帧，实心点是交给观测器的那一帧，连线是同一个锥桶；这一回合抽到相机晚 0.3 s、激光晚 0.1 s、轮速不晚。(b)(c)(d) 三个延迟的抽样分布，橙色是这个回合抽到的值。](notes/sim2real-actuator-and-latency/delay.gif)

两个细节让这件事"可复现、又和实车一致"：

- **每个回合的延迟来自"由种子派生的随机流"。** 所以同一个检查点可以精确重放同一个回合，调试时不会因为延迟抽样不同而对不上。
- **帧带着真实的采集时间戳和年龄进观测器。** 观测器自己的自运动补偿（上一篇里那个"每一步搬一遍路点"）因此和上车时跑的是**同一段代码、同一种输入**，而不是仿真里一个特殊的捷径。

**哪些没有装进去。** V6 这个训练池在代码里明确写着是"干净的池子：不注入故障和丢帧"。延迟、安装位置、符号和参数范围这些**系统性**的偏差都装进去了，但随机的丢帧、检测抖动和传感器故障没有；遇到丢帧时靠的是上一篇里的有界记忆和显式规则，而不是靠训练出来的鲁棒性。

## 微调，而不是重训

V5 的 Actor 是在旧仿真里训出来的、已经上过车的基线。V6 的做法是：

- 从 V5 的 Actor 和它最终的 Critic / target 出发，**不**重新随机初始化；
- 优化器、温度和回放重新开始，先只训 Critic（5k 步热身 + 前 20k 次更新），因为感知和电调物理变了，旧 Q 值不可信；
- Actor 学习率 1e-5，只有 Critic 的十分之一；
- 持续行为克隆，用新的教师（它知道板子遮挡的真实几何）产生标签。

结果用同一个 57 回合的开发集来读：**V5 的 Actor 放进 V6 仿真里是 28/57，且有 11 个回合倒车**（旧仿真里没有这种事）；微调到 600k 步，保留的 Actor 是 36/57，倒车的回合降到 1 个。这两个数是同一套仿真、同一批用例，可以比；但**不能**和 V5 当年在旧仿真上的 55/58 比。

## 上车

![实车片段：小车沿着单侧锥桶线行驶，经过一块靠着锥桶线放的板子（手机录像节选，已裁掉背景）。](notes/sim2real-actuator-and-latency/real-board.gif)

在实车上，V6 单侧控制器在一次演示里沿着单侧锥桶线绕过了这块板子，并把车交给了下一个模块（见[下一篇](/projects/chain-integration-switching)）。我对这一结果的口径很窄：

- 它是**一次**演示，不是重复试验的成功率；
- 它说明"装进了这些车上的缺陷之后，一个更接近车的仿真能训出一个上车可用的控制器"；
- 它**不**证明在统计意义上的工作包络。

## 还没解决的

- **无符号、延迟的轮速分不清"停下"和"倒转"。** 车上的倒车、中间的转向响应和刹车，还需要各自的标定，才能谈一般意义上的物理安全。
- **整套标定只对这辆车成立。** 换一辆车、换一块电池，至少要重新量那张稳态速度表。
- **只有一个训练种子，开发用例被反复使用。** 没有独立留出的测试，也没有多种子训练。
- **有些东西我只能标成"假设"。** 滚动阻力、维持阈值、停车倒车模型里的一些常数，都是基于日志估计的，我把它们标在了标定文件里，而不是当成测量。

## 经验小结

1. **每个数都写明出处，把"测到的"和"假设的"分开。** 只有零速根是辨识出来的，其余的标成假设，并且禁止悄悄重新拟合。
2. **用范围代替点。** 随机化覆盖的是不确定性，换车就要重新量。
3. **让仿真里的传感器链走和车上一样的代码：** 延迟、安装位置、符号、时间戳和年龄都原样带进观测器。
4. **旧模型出发做小学习率微调，先校准 Critic。** 比较只在同一套仿真、同一批用例上做。
5. **说清楚没装进去的东西：** 丢帧、检测抖动和传感器故障不在训练池里，靠的是有界记忆和显式规则。
