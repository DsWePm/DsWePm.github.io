在仿真里，控制器发出 0.30 的油门请求，小车慢慢往前走。在真车上，同样的 0.30，车纹丝不动：电调（电子调速器，把油门指令变成电机功率的部件）有一段“死区”，油门要超过某个值，电机才开始转。刹车以后如果继续给负的命令，真车还会倒着走，仿真里没有这回事。满舵时转过的角度，也不是仿真里设定的那个数。

仿真和实车之间的这类差距，统称 sim2real 差距。这一篇讲怎样把“车上量到的东西”一件件装进仿真，再在这个更接近真车的仿真里继续训练。范围先交代清楚：装进仿真的“实测特性”，主要是延迟、安装位置、无符号的读数，以及参数的不确定范围。没有往传感器里注入高斯噪声，也没有注入随机丢帧，这个训练池是“干净”的，后面会具体说明。

## 先量，再建模

仿真里原来的油门是“线性”的：命令大一点，推力就大一点。真车的电调不是这样。先记录了三件事。

- 死区。在静止的车上，请求 0.30 车不动，0.35 才起步。车一旦动起来，维持运动所需的油门又比起步时低。
- 稳态速度表。一组稳态（车速不再变化、驱动力和阻力平衡）下的“油门 → 速度”测量，见下表。更大的油门不是稳态，没有采用。
- 转向。满舵平均约 0.476 rad（左 0.463，右 0.489）。仿真里虚拟转向要乘 1.65 再截到 ±1。

| 油门 c | 0.30 | 0.32 | 0.34 | 0.36 | 0.38 | 0.40 | 0.42 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 稳态速度 / (m/s) | 0.27 | 0.56 | 0.67 | 0.86 | 0.99 | 1.08 | 1.16 |

稳态时，驱动力和阻力平衡。如果驱动力与油门成正比，阻力主要随速度增大，那么速度的平方应当与油门成线性关系。把速度平方除以 10，让数值与油门在同一量级，写成 v² / 10 = g · c + b，其中 c 是油门，g 和 b 是待定的常数。用最小二乘法拟合这七个点，得到 g = 1.0812，b = −0.3169，拟合曲线与测量点的最大偏差约 0.04 m/s。令 v = 0，可以解出零速根 c₀ = −b / g = 0.2931，也就是速度刚好降到零时对应的油门。这七个点是报告出来的数，手头没有原始的测量记录。

![(a) 稳态油门与速度的测量点（蓝点）和线性拟合（橙线），虚线是零速根 0.293。(b) 适配器：把控制器的虚拟请求 u 换成电调油门 c。u 不超过 0.005 时输出 0；起步时有一个由 0.34 升到 0.40 的下限，随起步后的时间 t 变化。(c) 电机模型：把油门 c 换成有效推力，每个回合随机抽一组参数（动画里依次画出几次抽样，图下方一行是当前这次抽到的参数）。蓝线是已经在动（0.5 m/s），橙线是从静止起步，虚线是维持和起步阈值。图最下面一行是每个回合抽样的范围。](notes/sim2real-actuator-and-latency/actuator.gif)

这里有一个限制：数据只能确定两个量，增益 g 和零速根 c₀。零速根里混着两样东西，维持运动所需的油门阈值 s 和滚动阻力 r，关系是 c₀ = s + r / g。这两个量单靠这张表分不开，只能确定它们的组合。于是取滚动阻力 r = 0.03，这是一个假设，由此得到 s = 0.2653。起步阈值 0.335 是另外给定的，不是从这张表拟合出来的。标定文件里写明了每个数的出处，并注明“这些数没有独立验证”，同时规定不允许悄悄重新拟合。

## 适配器和电机模型

有了这些，就可以写出两个方向的换算。

适配器的方向是“控制器 → 真实油门”。控制器输出一个“虚拟请求”u，适配器把拟合关系倒过来用：油门 c = 维持阈值 + (u + 滚动阻力) / 增益。u 很小（不超过 0.005）时输出 0，也就是零请求仍然是零。车速低于 0.12 m/s 时，油门还要不低于一个随起步时间变化的下限 min(0.40, 0.34 + 0.06 t)，t 是低速前进请求已经持续的时间。这样做，是因为静止的车必须先超过起步阈值才会动。

```python
throttle = hold + (u + rolling) / gain          # 把拟合关系倒过来用；零请求仍然输出 0
if speed < .12:                                  # 低速时，油门不能低于一个随时间升高的下限
    throttle = max(throttle, min(.40, .34 + .06 * t_since_start))
servo = clip(1.65 * steering)                    # 转向：乘 1.65，再限制在 ±1
```

电机模型在仿真里，方向相反，是“油门 → 推力”：油门不够起步，车就不动；不够维持，车被拖慢；超过之后才有推力。

```python
if v < .03 and c < start:  return 0.                       # 静摩擦：起步不了
if c < hold:               return -min(drag_cap, drag_k*v) # 低于维持阈值：被拖慢
return gain * (c - hold)                                   # 正常推力
```

## 用范围，不用单个数值

上面每个数都是在一辆车、一个电量、一个地面上量的。仿真里如果只放一组数值，策略就会学到“刚好适配这一组”。域随机化的做法是：训练时每个回合都从一个范围里重新抽一组参数，使策略不依赖某一组具体的数值。

| 参数 | 含义 | 抽样范围 |
| --- | --- | --- |
| 驱动增益 | 油门超过维持阈值后，每增加一点油门，推力增加多少 | 0.95 – 1.21 |
| 维持阈值 | 车已经在动时，维持运动所需的最小油门 | 0.245 – 0.285 |
| 起步阈值 | 静止的车起步所需的最小油门 | 0.33 – 0.40 |
| 满舵转角 | 满舵时车轮转过的角度 | 0.44 – 0.51 rad |
| 转向零偏 | 方向回中时的偏差 | −0.02 – 0.02 rad |
| 拖慢系数 | 油门低于维持阈值时，车被拖慢的强度 | 1.5 – 2.5 |

这些范围覆盖的是不确定性，并不是“任意未知的动力学”。换了车、换了电池、换了地面，它们不一定还成立，所以换车时不能直接沿用这些标定。

## 把延迟、安装位置和符号装进仿真

真车上还有几件仿真里原来没有的事，它们都被加进了新的仿真。

| 项目 | 车上的情况 | 仿真里怎么做 |
| --- | --- | --- |
| 相机延迟 | 帧晚到，车上的中位数约 0.206 s | 每个回合抽 1、2、3 步（概率 25%、50%、25%，一步 0.1 s） |
| 激光延迟 | 比相机新 | 抽 0、1、2 步（25%、50%、25%） |
| 轮速延迟 | 编码器读数 | 抽 0、1 步（各 50%） |
| 相机位置 | 在重心后 0.10 m | 观测从这个位置算。被板子挡住的锥桶，也从相机处追射线判断，不是从车身中心 |
| 激光位置 | 在重心前 0.20 m | 把距离换到车身坐标时用同样的平移 |
| 轮速符号 | 编码器只给大小，没有正负 | 只把绝对值交给观测程序，所以它分不清“停了”和“在倒车” |
| 电调倒车 | 停车后持续的负命令会让车倒着走 | 去掉仿真器里原有的“前进转倒车”闩锁（它只存在于仿真中），并把倒车记为不安全 |

选这几项，是因为延迟决定控制器看到的是多久以前的画面，安装位置决定“被挡住”是从哪里看，无符号的轮速决定车停下和倒车时观测程序能知道什么。这几件事车上本来就有，训练时必须遇到。

```python
CAMERA_DELAY_STEPS = ((1, .25), (2, .5), (3, .25))   # (延迟的步数, 概率)
LIDAR_DELAY_STEPS  = ((0, .25), (1, .5), (2, .25))
WHEEL_DELAY_STEPS  = ((0, .5), (1, .5))
...
# 观测程序拿到的是“几步以前”的那一帧，连同它真实的采集时间和年龄
cones, stamp, t = self.camera_frames[max(0, len(self.camera_frames) - 1 - self.camera_delay)]
```

![一个真实仿真回合里，观测程序拿到的相机帧与此刻最新的相机帧的差别。(a) 车身坐标系：空心圈是最新的相机帧，实心点是交给观测程序的那一帧，连线连的是同一个锥桶。这一回合抽到相机晚 0.3 s、激光晚 0.1 s、轮速不晚。(b)(c)(d) 三种延迟的抽样分布，橙色是这个回合抽到的值。](notes/sim2real-actuator-and-latency/delay.gif)

有两处做法保证这件事可以重复，并且与实车一致。每个回合的延迟来自由种子派生出来的随机序列，所以同一个检查点可以精确地重放同一个回合，调试时不会因为抽到不同的延迟而对不上。另外，帧带着真实的采集时间和年龄进入观测程序，第一篇讲的“每走一步把路点换算一遍”因此在仿真里和在车上运行的是同一段代码、同一种输入，仿真里没有特殊的捷径。

## 没有装进去的部分

新仿真的训练池，在代码里明确写着“干净”：不注入故障和丢帧。延迟、安装位置、符号和参数范围这类系统性的偏差都加进去了，随机丢帧、检测抖动和传感器故障没有。遇到丢帧时，靠的是第一篇讲的有限记忆和显式规则，而不是训练出来的鲁棒性。

## 微调，不从头训练

上一篇的 V5 是在旧仿真里训练出来的，已经上过车。新版本 V6 的做法是：

- 从 V5 的 Actor 和它最终的 Critic（含目标网络）出发，不重新随机初始化；
- 优化器、温度和回放缓冲区重新开始，先只训练 Critic（5,000 步热身，再加开头的 20,000 次更新），因为感知和电调特性变了，旧的打分不可信；
- Actor 的学习率取 1e-5，只有 Critic 的十分之一；
- 一直带着行为克隆，由新的教师（它知道板子遮挡的真实几何）给出命令标签。

结果用同一个 57 回合的开发集来读。V5 的 Actor 放进新仿真，成功 28/57，其中 11 个回合出现倒车（旧仿真里没有这种情况）。微调 600k 步以后，保留下来的 Actor 是 36/57，出现倒车的回合降到 1 个。这两个数来自同一套仿真、同一批用例，可以互相比较。它们不能与 V5 当年在旧仿真上的 55/58 比较，因为仿真不同。

## 上车

![实车片段：小车沿着单侧锥桶线行驶，经过一块靠着锥桶线放置的板子（手机录像节选，已裁掉背景）。](notes/sim2real-actuator-and-latency/real-board.gif)

在实车上，新的单侧控制器在一次演示中沿着单侧锥桶线绕过了这块板，并把车交给了下一个模块（见[第四篇](/projects/chain-integration-switching)）。这个结果的适用范围很窄：它只是一次演示，不是重复试验得到的成功率；它说明，装进车上的这些特性以后，一个更接近实车的仿真，训练得出了一个能在车上使用的控制器；它不能证明控制器在统计意义上的适用范围。

## 局限

- 轮速没有正负，又有延迟，分不清“停下”和“倒转”。车上的倒车、中间的转向响应和刹车，还需要各自的标定，才能谈一般意义上的物理安全。
- 整套标定只对这辆车成立。换一辆车、换一块电池，至少要重新量那张稳态速度表。
- 只有一个训练种子，开发用例被反复使用，没有独立留出的测试，也没有多个种子的训练。
- 有些量只能标成“假设”：滚动阻力、维持阈值，以及停车倒车模型里的一些常数，都是依据日志估计的，在标定文件里标明是假设，没有当作测量值。

## 小结

这一轮的做法可以归纳为：先量，再建模；测到的和假设的分开写，并在标定文件里写明出处；用范围代替单个数值，让每个回合重新抽一组参数；延迟、安装位置、符号和时间戳走与车上相同的代码；微调时先训练 Critic，学习率取小，并且只在同一套仿真里比较结果。
