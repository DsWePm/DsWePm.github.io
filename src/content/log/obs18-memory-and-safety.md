这是一辆小型自动驾驶小车的团队项目（一门机器人课程，路线是锥桶围出来的赛道，上面会放板子）里我负责的两块：**共享观测**和**单侧道路上的 SAC + PID 控制器**。这一篇讲前者，以及紧挨着它的那几层安全规则；控制器本身、训练和上车的事在后面几篇里。

先说清楚范围：我做的是"把检测到的锥桶变成一条局部道路参考和 18 个数"，不是重训检测器，也不是建地图。小车上跑的就是这一份标准库实现，仿真里调用的也是同一个类，没有第二套道路定义。

## 18 个数是什么

三个子队（双侧路、带障碍的双侧路、单侧路）共用同一份输入，所以每个数的含义都要固定下来。下表是 `field-probe-v0.2-18` 这版：

| 序号 | 含义 | 说明 |
| --- | --- | --- |
| 0–1 | 横向偏差、航向偏差 | 到最近参考线段的有符号距离；切线角取负 |
| 2 | 1 m 弧线目标 | 沿参考线前方 1 m 处，参考点在车身坐标里的横向位置 |
| 3 | 曲率 | 在有支撑的 1 m 窗口上取最大幅值的圆曲率 |
| 4 | 路宽 | 两边都看到时取实测，只看到一边时用先验 0.8 m |
| 5 | 参考地平线 | 剩余有支撑的弧长，截到 3 m |
| 6 | 参考年龄 | 这段参考里**最老端点的原始年龄**，截到 0.8 s |
| 7 | 前方距离 | 激光，±20° 扇区最小值 |
| 8–9 | 左 / 右通行余量 | 板子边缘相对道路的位置，减去假定车宽 0.39 m |
| 10–12 | 左 / 右 / 后方距离 | 激光扇区最小值 |
| 13–14 | 轮速、横摆率 | 轮速是无符号的 |
| 15–17 | 相机有效、激光有效、停车位标记 | 0 / 1 |

有一条约定贯穿全表：**未知就是 −1，并且和"饱和"分开。** 距离是 1 只表示"这个扇区没有回波，且别处有点"，不证明那里能走；−1 也不是"直路"。这条约定后面会反复用到。

![真实 V6 仿真里的一次过板，观测器用的是仓库里钉死的 V2 版本。板子挡住锥桶以后，视野里的锥桶一个个消失，保留的道路（青色）越缩越短，参考地平线从约 2 m 降到 0；1 m 目标和曲率先变成 −1，横偏和航向还能用，再往后全部丢失，直到车摆出去重新看到锥桶才重新建立参考。底部是当前的 18 个数，斜线加问号表示未知。](notes/obs18-memory-and-safety/obs18-memory.gif)

## 记忆：只记一小段，而且记得很"老实"

锥桶会被板子挡住，相机视野也很窄，所以光看当前一帧不够用。但我不想要 SLAM，也不想要一张持久的赛道地图，那样出错的方式太多。最后的做法是**有界的车身坐标系历史**：

- **只保留一小段。** 最多 24 个路点，最多 10 s（实车用的就是这个检查点；底层默认只有 0.8 s），每一步用轮速和横摆率对所有路点做刚体运动补偿。
- **保留原始采集时间。** 路点的"年龄"永远是它被相机看到那一刻起算的，运动补偿**不会**让它变新。obs18 里的第 6 位因此能如实说"这段参考有多旧"。
- **新测量要通过"有支撑的连接"才被接受。** 同一个时间戳的帧不重复处理；相邻路点间隙超过 1.2 m、折叠、偏移几何畸形的一律拒绝；新旧两段只有在方向一致（约 45° 以内）、衔接距离小于 0.35 m 时才拼在一起；不去连接两个隔空的端点，也不去延长看不见的那一段。
- **单侧时宽度只是假设。** 只看到一排锥桶时，参考线是把这一排向内平移半个路宽得到的，这个宽度是先验（默认 0.8 m），不是测出来的"另一侧"。
- **轮速不变不等于车停了。** 轮速读数可能是被保持的旧值。观测器只在"相机连续几帧里有三个互相匹配的同色锥桶、跨度至少 0.4 m、且两个时间间隔一致"时，才允许反驳至少 8 cm 的上报位移。

```python
# 保留的路点每一步都按当前运动搬一遍，时间戳不动
moved = [self.move(p, speed * dt, yaw * dt) for p in self.route]
self.route, self.times = self.trim_route(moved, self.times, now)
...
age = now - min(self.times[index:index + 2])   # 来自原始采集时间
```

这样做的效果就是上面那张动图里看到的：参考不是突然消失，而是**逐渐变短、逐渐变老**，obs18 的地平线、年龄、"有没有 1 m 目标"这三个位置会按顺序告诉控制器"支撑在减少"。控制器看到的是一个可以降级的信号，不是一个突然的 0。

## 取舍：哪些东西故意不放进 18 维

这个接口不是一开始就长这样的。下面几次改动都是被队友的反馈或失败案例推动的：

1. **先估道路，不重训检测。** 一开始我先把课程提供的锥桶检测器的输出追了一遍，把感知和控制的边界跟队友讲清楚，把精力放在"把检测变成共享参考"和"文档化的仿真/实车接口"上。最早的 17 维草案后来变成了 18 维合同。
2. **只记有限的支撑。** 队友先做了一版路记忆来对付"绕板时丢锥桶"，我在它的基础上修了几何、拼接和时间处理，合进了团队的开发分支。事后看，**保留原始采集时间、拒绝没有支撑的拼接**，比不停刷新旧点重要得多。
3. **让转弯信息对学习器有用。** 负责 PPO 的队友反馈：一个简单的前向目标比我们不断抖动的曲率更容易学。我用录下来的输入和受控仿真比较之后，改成了"固定 1 m 弧线处的横向位置 + 有支撑 1 m 窗口上的曲率"。**长度还是 18，但两位特征的含义变了，所以旧权重不能直接用**，长度相同不等于兼容。
4. **不用更多特征去掩盖不确定性。** 更清楚的转弯提示并没有解决"邻道锥桶被认成本道"的关联问题。我选择让这个不确定性保持显式，而不是再加特征把它藏起来。
5. **参考修好了不等于控制成功。** S 弯、L 弯的拼接说明：一条看上去合理甚至更长的线，仍然可能是错的，或者车根本开不过去。

用同一批保存下来的输入重放，我看到的证据是这样的（都是历史仿真，不是最终 V6，也不是实车成功率）：

| 检查 | 记录的结果 | 我的结论 |
| --- | --- | --- |
| 同输入重放 V2 | 752 条序列 / 58,343 帧；40,691 帧有独立参考，其中 804 帧由错变对，2 帧变成未知，没有新增超过 0.4 m 的误差 | 这批数据上有更多可用目标，不是驾驶成功率 |
| 两个镜像的外 L 弯 | 最大参考误差 0.200 → 0.0543 m | 一个具体的转角故障变好了，两个例子不能说明总体精度 |
| 锐角 L 弯 + 冻结的 MPC | 两个观测器下都是 0/20 完成，碰撞接触 2 → 5 | 参考更好没能让锐角变安全，我把失败案例留着 |

最后一条很重要：**我早期的周记写过"和仿真真值几乎吻合"，后来反例出现，我把这句话收窄到了被测条件内。** 准确性、连续性、有支撑的预览、车辆能不能安全开过去，必须分开检查。

## 提速：只改计算，不改输出

观测器是纯 Python，每个控制步都要跑一遍。车上 CPU 比笔记本慢得多，所以我在 10 月 22 日做了一次**"只改计算、输出逐帧不变"**的优化：

- **空间网格代替两两比较。** "激光点是不是落在某个锥桶 0.12 m 内"和"车身扫掠盒里有没有障碍点"原来是两重循环；现在对较大的批次临时建一个网格（锥桶用 0.25 m 的格子，扫掠盒用 0.5 m 的格子），每个点只查周围几格。最终判定仍然用**原来的严格比较**，网格只负责少查几对，不降采样，也不放宽阈值。
- **线段表只准备一次。** 一批激光点投影到参考线上，每个点原来都要重算每段的长度平方、起点偏移等；现在每个批次准备一张预处理过的线段表，再逐点投影。
- **缓存每束激光的 cos / sin。** 同一个激光规格（束数、起始角、步进）只算一次，上限 2048 束；规格变了、束数超限或角度准备失败就回到原来的转换路径。
- **快照复制只共享"已验证不可变的标量元组"。** 原来每一步都对整批检测和激光点 `deepcopy`；现在可变的列表仍然克隆，只把确认是标量元组的元素共享，并且预先种好 `deepcopy` 的 memo，别名、环和未知载荷的语义不变。
- 其余：直线拟合复用居中后的坐标；车后方已经被最终判据排除的点提前跳过。

```python
# 锥桶放进 0.25 m 的格子里；一个激光点只和周围几个格子里的锥桶比
cone_grid = {}
for c in current_cones:
    cone_grid.setdefault((math.floor(c[0] * 4.0), math.floor(c[1] * 4.0)), []).append(c)
...
# 命中格子里的候选，再用原来的严格距离判断是不是"锥桶自己的回波"
```

**怎么证明没改输出：** 把旧版（`a6049ce`）和新版（`42318b2`）放在同一批保存下来的输入上重放，共 **1,240 条序列 / 143,953 帧**，完整观测输出和每个点的采集时间逐帧一致，唯一不同的是计算耗时。CI 里不断言耗时：笔记本的时间不是车上的期限。

**这次我在本机用仓库自带的基准脚本又量了一遍**（2048 束激光，每次 `step`；Windows 笔记本，不是车）：

| 版本 | 中位数 | P95 |
| --- | --- | --- |
| 优化前 `a6049ce` | 约 23.3 ms | 24–26 ms |
| 优化后 `42318b2` | 约 9.0–9.3 ms | 10.7–12 ms |

约 **2.5 倍**。要注意这只是观测器一步的耗时，整个回调还要加上传感器年龄、策略和守卫，所以真正的预算在别处（下一篇会讲）。

## 安全层：从 obs18 到电调，每一层只管一件事

观测只负责"看"，不选策略，也不使能车辆。真正决定车怎么动的是后面的命令路径，我把它拆成几层，**每一层只能让命令更安全，不能更冒险**：

![从 obs18 到电调的最终命令路径（V6 SAC + PID 的最终组合）。学习部分在可用余量内提出残差；规则只处理有边界的特例；守卫和适配器负责最后的限制与单位。](notes/obs18-memory-and-safety/command-path.svg)

1. **学习部分：SAC 残差 + PID 底座。** PID 只读 obs18，积分增益为零；SAC 输出的残差按"可用余量"混合，保证命令永远在 [−1, 1] 里（下一篇细讲）。
2. **绕障规则。** 一块贴着锥桶线的板子会把它后面的锥桶全部挡住，obs18 的参考和 SAC 的残差都没法把这个动作做完。规则接管：把航位推算的中心线平移到**更宽那一侧间隙的中点**（要放得下车才行），以 0.35 m/s 做 0.8 m 前瞻的纯跟踪；板子一旦离开激光视野，就靠里程计记住它的位置；等车尾越过板子、obs18 重新有效再交还。
3. **速度调速器。** 最终的虚拟驱动量被限制在 0.8 m/s 对应的值以内。这是目标上限，不是物理速度保证。
4. **最终守卫。** 沿参考线检查车身扫掠盒（车头 0.37 m、车尾 0.27 m、半宽 0.195 m）：车身 0.39 m 加每侧 0.03 m 余量，共需要 0.45 m。**同侧空间不够就停车，不在板子旁边临时换边。** 有界延续（绕障时丢了路也允许再走一小段）要求近期有绕障证据、激光新鲜且非空、单步不超过 0.12 s，并且最多 3 s / 1.5 m、速度 0.35 m/s。
5. **Car13 适配器和电调刹车锁。** 把虚拟驱动 / 转向换成真实的油门和舵机指令，转向只在这里取反一次；近停车状态下不允许负命令把车倒起来。

```python
# 规则里决定绕哪一侧：看哪边的间隙放得下车，并取更宽一侧的中点
need = CAR_WIDTH_M + 2 * SIDE_MARGIN_M
hides = not valid or float(obs[5]) * 3 <= near - s0 + HIDE_MARGIN_M   # 板子挡住了参考
one_sided = min(left_gap, right_gap) < need <= max(left_gap, right_gap)
if not self.active and wanted and max(left_gap, right_gap) >= need and near - s0 < TRIGGER_DISTANCE_M:
    self.active = True
    self.target_d = (hi + width / 2) / 2 if left_gap >= right_gap else (lo - width / 2) / 2
```

![同一条命令路径在真实 V6 仿真里过一块贴着锥桶线的板子（弯道上）。青色虚线是观测器自己的参考，淡青色的盒子是同一套扫掠盒检查，碰到板子的那一格变红（BLOCKED）。这时规则接管：琥珀色走廊从更宽一侧间隙的中点穿过，板子被里程计记住；车尾清过板子后交还给 SAC + PID。下面三张图依次是速度、驱动和转向，琥珀色底是规则接管的时间段，虚线是 0.8 m/s 的调速器上限。](notes/obs18-memory-and-safety/safe-layer.gif)

### 这套层层加码的东西，有几件事我是从日志里学来的

- **同一个缝隙，两个规则可以互相矛盾。** 早期绕障规则要求缝隙 ≥ 0.33 m，而最终扫掠检查要 0.45 m，同一个缝隙上一个说"能过"、一个说"不能过"，车就停在板子前。后来把规则里的车宽改成 0.39 m、两侧各 0.03 m，前后悬也换成 0.37 / 0.27 m，让两者用同一个包络。这是**一致性修复，不是新的车宽测量**。
- **删掉一个守卫，车不一定会重新走。** 我对比了两份实车诊断日志（不是那次成功的演示）：一次停车是"绕障许可 3 s 到期且没有重新接上道路"（相机其实还看得到锥桶，所以不能用"相机什么都没看到"来解释），另一次是"地平线 2.85 m，但扫掠余量只有约 0.025 m"，后来规则本身也要求停车。
- **"看不见"和"路断了"是两件事。** 有界绕障许可存在期间，我暂停了仅由"没有路 / 没有锥桶"触发的停车搜索计时；已经确认的车位仍然优先。
- **宁可停，也不猜。** 没有近端支撑，或者扫掠通道不可行，即使还看得到一些锥桶也会停。

这套组合在仿真里的留出集上，139 个用例成功 111 个，没有碰撞，但有 10 次越界、17 次停滞和 1 次倒车；规则在其中 108 个用例里介入过。这一版记录用的还是较早的 0.33 m 通行需求（最终集成后的包络是 0.45 m），是组件级的开发结果，不是整条链的 139 次测试，也不是实车成功率。

## 还没解决的

- **一个静态的缝隙不能证明车能转过去。** 车身扫掠、相机遮挡和转向饱和必须一起检查。
- **单侧时的宽度是假设。** 改这个先验会同时改参考和通行余量，不能说成"发现了真实路宽"。
- **有限的历史只能桥接短暂的遮挡。** 折叠的路、相邻的另一排锥桶、延迟或被保持的运动反馈，仍然是误差来源；未知的特征保持未知，而不是被编造出一段延伸。
- **更多检查需要同步的原始激光、锥桶帧和独立位姿。** 这套日志里没有，所以上面的结论都标了范围。
