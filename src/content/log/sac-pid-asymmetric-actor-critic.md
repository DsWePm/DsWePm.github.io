接着上一篇的观测，这一篇讲**单侧道路上的控制器**：PID 做底座，SAC 学一个残差，再加几层规则（规则在上一篇里）。重点是三个问题：为什么要把 Actor 和 Critic 做成不对称的；车上怎么保证延迟；训练里怎么保证最后拿到的是一个"真的更好"的模型。

## 结构：PID 做底座，SAC 学残差

SAC 不直接输出油门和转向，而是在 PID 的命令上加一个**残差**。PID 是 obs18 的纯函数，不带积分状态：

- 驱动 = 速度前馈 + 速度比例项，目标速度来自参考地平线和曲率；
- 转向 = 横偏 + 航向 + 横摆率阻尼 + 1 m 弧线目标的前瞻项；
- 参考无效时，PID 自己刹车、转向归零，不做任何猜测。

积分增益取零是有意的：**这样 Critic 看到的 18 个数就足够描述 PID 的行为**，没有藏在控制器里的积分状态。（但 18 个数仍然不包含规则和历史的全部状态，所以我不声称严格的马尔可夫性或收敛保证。）

残差和 PID 底座 `p` 的混合，用的是"可用余量"：

```python
correction = np.clip(scale * residual, -1., 1.)
room = np.where(correction >= 0, 1. - base, 1. + base)   # 往哪个方向，就用哪一侧剩下的余量
command = np.clip(base + room * correction, -1., 1.)
```

![PID 底座 p（灰）、SAC 残差 a（青）和混合后的命令（琥珀色）。左边是混合函数本身：不管底座 p 在哪，残差从 −1 到 +1 都恰好扫满 [−1, 1]，a = 0 时命令就等于 PID；圆点是当前这一步在曲线上的位置。右边是真实 V6 仿真里一段过板时的时间序列。规则接管的时间段混合器不起作用。公式的结果和仿真里记录的命令逐步比较，最大差为 0。](notes/sac-pid-asymmetric-actor-critic/mixer.gif)

这个形式有三个好处：

1. **零残差就是 PID。** 训练刚开始、网络输出接近 0 的时候，车的行为就是一个能用的 PID，不用从零探索。
2. **命令不会被截断。** 残差用"剩下的余量"缩放，所以不会推到 ±1 之外去做被 `clip` 吃掉的无效动作，也就不会因为 `clip` 把梯度吃掉。
3. **失败时有处可退。** 参考无效的行（"residual ignored"）不给 SAC 任何梯度，只交给 PID 的刹车和后面的 BC 标签去学。

训练时的 Critic 吃的不是网络的原始残差，而是**混合并经过命令守卫之后的虚拟请求** u（还没有换成真实的电调油门）：我用 torch 写了一份 PID + 混合器 + 输出适配器的可微复刻（`applied_command`），让 Q(o, u) 评价的是"车真正会去做的那个命令"。

## 不对称：Actor 小，Critic 大，教师只在训练时出现

![训练时和上车时各有什么。训练机上有仿真器、教师、GPU 上的回放、两个 Critic 和 Actor；上车只带 6 个数组（actor_mean.npz），用 NumPy 做均值推理，再接 PID、混合器、规则和守卫。教师的标签只通过 BC 损失进入 Actor。](notes/sac-pid-asymmetric-actor-critic/asymmetric.svg)

| 部分 | 结构 | 参数量 | 在哪里 |
| --- | --- | --- | --- |
| Actor | 18 → 256 → 256 → 2（ReLU，tanh 残差均值） | 71,170 | 训练 + 上车 |
| 对数标准差头 | 与 Actor 共用隐藏层 | 仅训练 | 训练 |
| 两个独立 Critic | 20 → 512 → 512 → 1，无 LayerNorm | 各 273,921 | 仅训练 |
| 教师 | 知道道路和板子几何 | — | 仅训练（只给 BC 标签） |

模块名里的 `FT512`，指的是 **Critic 宽度 512**，不是 512 宽的 Actor。这种不对称带来的好处：

- **上车的东西小到可以被检查。** 车上只有 6 个数组（三层权重和偏置）、一段 NumPy 前向，不需要 torch、不需要 GPU，也没有第二套模型加载器。
- **Critic 可以放心地大。** 它只在学习时要准，部署时不存在，所以宽度和训练开销都不影响延迟。
- **特权信息不泄露到部署输入里。** 教师能看到道路和板子的真实几何，但这些只变成 BC 的"该输出什么命令"的标签，Actor 的输入仍然是同样的 18 个数。训练和上车吃的是同一个观测。
- **Critic 吃的是执行命令。** 见上一节：Q 值评价的是车真正会做的事。

要诚实地说一句：**更大的 Critic 不一定更好。** 我比较过 FT512 和一个 1024 宽加 LayerNorm 的 Critic（FT1024LN），在开发集上是 55/58 对 53/58，FT512 反而略好，安全性也更好。但这两个模型的来源和归一化不一样，所以这**不是一次纯粹的网络宽度实验**，不能据此说"更大没有用"。

## 车上怎么保证延迟

**先量，再决定要不要为延迟牺牲网络大小。** 我在 10 月 22 日用 Car20（未使能、传感器服务在跑）量过推理：

- 单独跑 Actor 的 P99 是 1.529 ms，PID + Actor 的 P99 是 3.560 ms（901 次调用的一条流）。
- 另一组对比里，64 / 128 / 256 宽的网络放在一起量，P99 都在 1–3.4 ms 之间；其中 128 / 256 是随机权重，**只用来测算力，不代表训练好的策略**，也不是端到端的 ROS 延迟。
- 后来整条集成链在车上一步的中位数是 49 ms，最大 131 ms，远低于 0.5 s 的期限；控制周期是 10 Hz，也就是 100 ms 一拍。

我在笔记本上把真实推理路径也重新量了一遍（同一份 hold3 600k 权重，真实观测，20,000 次调用）：

![推理耗时的"阶梯"：本机测到的 NumPy Actor、整条命令路径、同一个网络在 torch CPU 上的耗时，对照车上的 Car20 和整条链的实测，以及 100 ms 的控制周期和 0.5 s 的期限。对数坐标。](notes/sac-pid-asymmetric-actor-critic/latency.gif)

| 路径（Windows 笔记本，单线程） | 中位数 | P99 |
| --- | --- | --- |
| NumPy Actor 18-256-256-2 | 21 µs | 34 µs |
| Actor + PID + 混合 + 调速器 + 适配器 | 107 µs | 256 µs |
| 同一个 Actor，torch CPU | 56 µs | 117 µs |

结论有两条：

1. **推理不是预算。** 从微秒到毫秒，离 100 ms 一拍差两到四个数量级。把网络做小、用 NumPy，是为了让部署足够简单，而不是为了抠延迟。
2. **真正的预算在传感器的年龄。** 车上记录的相机中位年龄约 264 ms，激光 153 ms；完整的策略计算耗时中位 50 ms，最大 62.7 ms；步周期中位 100.2 ms（这些来自两份实车诊断日志共 360 行，不是那次成功的演示）。"网络很快"不意味着没有延迟，被保持或过期的反馈照样会影响行为。

车上保证延迟的做法，一条一条说：

- **只带 NumPy。** 全部运行时代码、固定参数和权重都内嵌在一个节点文件里，车上只需要 ROS 的依赖和 NumPy；模块在节点启动时加载一次，切换控制器时不会重新解码权重。
- **每一步的工作量有上限。** 观测器对超大的帧（激光超过 2048 点、检测超过 40 个）直接停车，不截断后再声称"剩下的空间是空的"；缓存、空间网格都是为了让一步的最坏时间有界。
- **延迟约束算的是整个回调。** 有界延续那条"单步不超过 0.12 s"的约束，量的是整个回调，不只是 Actor。
- **不用耗时做 CI 断言。** 笔记本的时间不是车上的期限；车上的数用 Car20 的实测。

## 训练怎么保证效果

我最终用的是 V6：从已经上过车的 V5 FT512 出发，在一个带真实传感器和电调特性的仿真里继续微调（那个仿真在下一篇讲）。下面是我觉得对结果最重要的几件事。

![V6 hold3 的真实训练日志，0 → 600k 步。左上是训练窗口内的成功率；右上是每 20k 步在 57 个固定开发回合上的成功数（点是候选，绿色表示被采纳为"保留的 Actor"，线是当前保留的 Actor）；左下是 Critic 损失和 BC 的均方误差；右下是熵系数和 BC 权重。灰色阴影是 Actor 冻结、只训练 Critic 的时间段。](notes/sac-pid-asymmetric-actor-critic/training.gif)

1. **先冻结 Actor，只训练 Critic。** 起点是 V5 的 Actor 加它最终的 Critic 和 target，但感知和电调物理变了，旧的 Q 值不再可信。所以先热身 5k 步，再让前 20k 次更新只训练 Critic，然后才联合微调。优化器、熵温度和回放都从头开始：这是一个新的微调实验，不是旧分布的原样续训。
2. **持续模仿，权重大。** SAC 的 Actor 损失里始终带着行为克隆项，权重约 80。标签来自 V6 的"保持教师"，包括专门的保持阶段样本和 432 条额外的贴锥示范；**失败的教师回合和它们的前缀一律排除**，不因为前半段看起来好就留下。
3. **学习率很小。** Actor 1e-5，Critic 和温度 1e-4，γ = 0.99，τ = 0.005，批 256，回放 200,000，初始熵系数 0.1，目标熵 −2。
4. **任务池固定比例。** 每个回合：25% 空路、55% 可过板（其中一半贴着锥桶线）、20% 完全堵死。板子贴着锥桶线是最难的一类，所以要刻意多采。
5. **奖励只当训练信号。** 前进奖励只在道路已知时给，并按航向误差打折（`max(0, cos e)`）；时间、横偏、航向、转向用力、超速、"路未知还跑得快"都有惩罚；靠近板子时把跟踪权重从 2.0 降到 0.35，免得为了贴中线而不敢绕；安全过板 +5、跑完 +10、确认堵路后停车 +5，碰撞 / 越界 / 禁止的倒车 −50。**停滞算采样截断并做价值自举，不当成"失败终止"**，这样"本来能过却停了"和"本来就该停"才能分开。
6. **用一个不依赖奖励的开发集选模型。** 每 20k 步，在 57 个固定回合上评一遍候选 Actor；只有它在"成功数优先，其次绕板成功、碰撞、越界"的顺序上更好，才替换"保留的 Actor"，否则回退。

这条曲线里有几个我觉得值得写下来的东西：

- **刚开始微调时变差了。** 40k–120k 步的开发集成功数掉到 24–27（碰撞一度到 11），之后才回升。如果只看训练曲线，很容易在这里就放弃。
- **最后上车的不是最后一个检查点。** 被保留的是 580k 步那一次（开发集 36/57、绕板成功 27、碰撞 4、越界 3）；最后一个检查点（600k）只有 33/57。起点是 V5 的 Actor 在新仿真里的 28/57。
- **长训练不等于更好。** 300k 之后接着训练到 600k（用 `--extend`），训练窗口里的成功率几乎没变（约 0.6），开发集上的最好成绩从 34 提到 36。Critic 损失和 BC 误差都早早平了。
- **单种子，示范只选了成功的。** 方差和覆盖都有限，开发集排名不是硬性的安全证明。

另外有两个评测上的习惯：

- **训练奖励从不当验收标准。** 子队共用的评分与训练奖励无关（完成 40、安全过板 20、堵路安全停车 10、安全进度 20、完成速度 10，满分 100），固定的 200 / 160 / 70 例套件有指纹和成对种子，事故数和类别分母一起报。
- **先证明教师能做，再怪学生。** V5 的教师最初只通过了 150 个冻结资格回合里的 118 个；修了几何和可见性后到 132 个，仍有失败。我检查完整回合，只用通过的示范，而不是接受"前半段看着不错"的失败回合。

## 我从这里面学到的

完成 100 万步，或者拿到更高的平均分，都不够。我需要**同时**看失败类别、教师的覆盖、"请求的动作"和"实际执行的动作"，以及被支持的道路。最后的选择是**学习 + 实测的执行器 + 有边界的显式规则**的组合；我没有假设"再训久一点"能修好每一种看不见的东西。
